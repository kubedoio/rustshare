# RustShare v0.7.0

**Final pre-Elembra RustShare release.**

This is the last stable release of the current RustShare (Module-era)
architecture. The next development line introduces the breaking Elembra
Application architecture (tracked by #196 / #209 / #210+); v0.7.0 remains the
final release using the current RustShare architecture. See
[`docs/releases/pre-elembra-boundary.md`](docs/releases/pre-elembra-boundary.md).

## Highlights

- **Mail daily-use improvements** — responsive three-pane webmail client, IMAP
  selected import and archive jobs, reliable move/archive actions, deterministic
  date sorting (#182, #184).
- **Safer Mail privacy & download handling** — remote images blocked by default
  with per-message opt-in (#181); injection-safe, sanitized download filenames on
  every download path (#183).
- **Vault editing reliability** — conflict-safe WebUI Markdown editing with
  optimistic revision locking, 409 conflict recovery, and per-vault write
  policies (#185).
- **Deployment & bootstrap improvements** — documented secret generation,
  automatic object-storage bucket bootstrap, health/readiness checks, share
  revocation coverage in the launch smoke, production Compose contract hardening
  (#132, #154).
- **Security & tenant-isolation hardening** — permission-aware AI indexing with
  fail-closed ACLs, safe content-addressed blob garbage collection, production
  secret validation.
- **Object-storage reliability** — deterministic bucket bootstrap errors,
  blob-GC lifecycle safety, pinned RustFS digest.
- **WebUI usability fixes** — bounded bug-bash pass across login, dashboard,
  files, mail, shares, and admin (#186).
- **Operational/release hardening** — unified Cargo workspace, tag-triggered
  release automation, DCO enforcement, OpenAPI contract freshness checks, fixed
  backup and restore-drill tooling.

## Upgrade notes

- **Back up first**: `./scripts/backup-stack.sh` (see
  `docs/runbooks/backup-restore.md`).
- **Migrations are forward-only** and run automatically on first start
  (`sqlx migrate run`). Rollback = restore the pre-upgrade backup and redeploy
  the previous release — do **not** run the old binary against a migrated
  database. See `docs/upgrading.md`.
- **Mail behavior changes**: remote images are blocked by default in message
  previews and imported bodies (opt in per message). Plaintext SMTP modes
  persisted before this release are rejected at send/test time.
- **Mail module is disabled by default**: after upgrading (or on fresh installs),
  enable the Mail module in admin module settings (or `POST
  /api/v1/admin/modules/mail/enable`) before the Mail UI/API responds.
- **New environment variables**: `RUSTSHARE_ALLOW_INTERNAL_MAIL_SERVERS`
  (default `false`), `RUSTSHARE_MAIL_TLS_ACCEPT_INVALID_CERTS` (default
  `internal`), `RUSTSHARE_OBJECT_STORE_AUTO_CREATE_BUCKET` (default `true`),
  `RUSTSHARE_OBJECT_GC_*` / `RUSTSHARE_BLOB_LOCK_POOL_*` operator controls.

## Known limitations

- The desktop client (`apps/desktop`) remains an early-prototype CLI/daemon
  (version 0.4.0); not part of the v0.7.0 server release gates.
- OIDC per-IdP validation and the full clean-Linux support matrix
  (Ubuntu 22.04 / Debian 12) remain target-environment launch gates; v0.7.0 was
  validated on the supported Docker Compose path (local Linux) and Ubuntu 24.04.
- Production TLS termination is operator-managed (same-host reverse proxy);
  see `docs/DEPLOYMENT.md`.
- `npm audit` reports 2 moderate advisories in the production dependency chain
  (DOMPurify via monaco-editor); no high/critical. The only offered fix is a
  breaking downgrade of `monaco-editor` — deferred, tracked upstream.

## Architecture note
