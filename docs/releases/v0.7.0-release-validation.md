## Known limitations (accepted non-blockers)

1. **Frontend dependency advisories (moderate only after fix)**: `npm audit --audit-level=high`
   passes (exit 0). Three high-severity `nanoid` advisories found during PR CI
   were fixed by pinning patched `nanoid` versions via npm `overrides`
   (`^3.3.17` / `^5.1.16`). Two moderate findings remain in the production
   dependency chain (`dompurify <=3.4.12` XSS advisory via `monaco-editor`);
   the only offered fix is a breaking downgrade of `monaco-editor` — deferred,
   tracked upstream.
2. **Parallel-suite DB deadlock flake**: `restore_contract::test_multiple_restores_preserve_history`
   hit a PostgreSQL deadlock once under parallel suite load; passes solo (1/1)
   and in the full contracts re-run (136/136). Classified as a test-concurrency
   flake, not a product defect. Tracked as a follow-up.
3. **Local `backend/.env` leakage in one e2e test**: `e2e_sample::test_health_endpoint`
   fails only when the local gitignored `backend/.env` (absent in CI) leaks into
   the harness via `dotenv()`; passes from a `.env`-free CWD. Environmental.
4. **Orphaned websocket test files**: `backend/server/tests/websocket_{sync,catchup,multidevice}.rs`
   are not wired into `Cargo.toml` and are never compiled/run by any cargo
   invocation. Pre-existing; out of scope for v0.7.0.
5. **CI integration coverage gap**: the main CI test job runs
   `cargo test --workspace --all-features --lib --test openapi_export_test` and
   the integration job runs only `-- --ignored`, so the non-ignored integration
   test binaries (admin/group-sharing/invites/public-share-header/search-authz/
   module-service) never execute in CI. All were executed and passed for this
   release locally; recommending a follow-up to wire them into CI.
6. **IMAP live-connection test skip**: `imap_selected_import_creates_job_and_imports_messages`
   skips without a public `IMAP_TEST_HOST` (SSRF protection rejects
   internal/loopback hosts); identical behavior in CI. Live-provider IMAP/SMTP
   paths are covered by unit tests with fixtures; real-provider connectivity is
   a target-environment validation item.
7. **External/manual gates not executable in this environment**: the full clean
   Linux support matrix for the quickstart (#132: Ubuntu 22.04 + Debian 12 clean
   VMs; only Ubuntu 24.04 was validated), an external staging deployment against
   a copy of production data, and external security assessment (pentest) remain
   target-environment launch gates per `docs/PRODUCTION_READINESS.md` — they are
   not software-release gates for v0.7.0 and are recorded here for traceability.
8. **Release tag signing**: the release process requires a GPG-signed tag; the
   release environment has no GPG key available. Tag signing is handled per the
   decision recorded in the release PR/issue (see Final decision).
9. **`rustshare-crypto` does not compile standalone with default features**:
   `cargo check -p rustshare-crypto --lib` fails (argon2's `getrandom` feature
   is only enabled through workspace feature unification). The workspace and
   release builds (`--workspace --all-features`, as CI runs them) compile fine;
   this is a pre-existing crate-manifest quirk, recorded for transparency, not a
   v0.7.0 regression.
