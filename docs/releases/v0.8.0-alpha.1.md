# Elembra v0.8.0-alpha.1

**Alpha preview — not production-stable.**

This is the first release on the Elembra Application line. APIs and data models
may still change; no production upgrade path is implied between alpha
releases. v0.7.0 remains the final pre-Elembra RustShare release and the
reproducible baseline for the Elembra migration (see
[`docs/releases/pre-elembra-boundary.md`](pre-elembra-boundary.md)).

## What's in it

- **Elembra Application architecture** — the pre-release Module product
  boundary is replaced by declarative Elembra Applications (ADR-0030):
  tenant/workspace enablement, `/apps/...` UI routes, and the
  `/api/v1/applications/...` registry (#210).
- **Files / ResourceRef** — cross-application identity and resource contracts
  (ADR-0032, v1alpha1): `PrincipalContext`, opaque `ResourceRef` with canonical
  `elembra://` URIs, and the `ResourceOwner` source-authorization contract
  (#211). Elembra Files is the first owner adapter.
- **Buzz-powered Chat** — Chat is a read surface for Buzz communities/channels/
  messages, with browser-held signing keys and client-direct NIP-42 publish
  (#242 milestone).
- **Zero-config Chat bootstrap** — enabling Chat auto-provisions the deployment
  Buzz community (auto mode) with an admin provisioning page (#220+).
- **Buzz authoritative authorization** — every channel/message decision comes
  from the community's authoritative Buzz relay over the v1alpha1 contract:
  NIP-98 authenticated, kind-19030 signed, pinned + freshness verified,
  fail-closed (#245). The live conformance suite proves the production-authority
  proofs against the real relay.
- **Recipient-visible Files attachments** — sender-side `elembra-ref` tags on
  messages; the observation index retains identifier-only refs and the timeline
  reauthorizes through Files at read time (#242).
- **Company Memory** — Buzz chat activity projects into the Memory catalog as
  durable references (per-workspace policy, default OFF), with an admin
  reconciliation endpoint.
- **Unified Search** — one `POST /api/v1/search` returns ranked Files/Notes and
  Buzz Chat results; every result is reauthorized by its current owning source
  (ADR-0036).
- **Ask at Workspace / Folder / Note / Channel scopes** — a shared `/ask`
  experience with grounded citations and permission-aware citation opening;
  answers are generated only from freshly authorized source content.
- **Durable Integration Events** — transactional PostgreSQL outbox with
  CloudEvents-compatible envelopes (ADR-0031, v1alpha1).

## Buzz image

Chat uses the pinned supported Buzz relay image
`ghcr.io/kubedoio/buzz:sha-8ce4dac` (merged kubedoio/buzz main, provenance
attested). See the alpha runbook for pinning and verification.

## Known limitations

- **No reply/thread composer** — the canonical thread wire format is confirmed
  (NIP-29 `["h", <channel-uuid>]` + NIP-10 `e` tags), but the reply UI is a
  future milestone (#243).
- **Ask requires an operator-configured OpenAI-compatible provider** — with
  `ELEMBRA_LLM_API_KEY` unset, Ask is gated (`ask_available=false`, 503) and
  never falls back to another provider (#244).
- **Manual Workspace↔Community mapping remains the explicit existing-deployment
  mode** — zero-config auto-provisioning is the dogfood default; existing
  deployments connect their workspace to a community explicitly.
- **Upstream Buzz fork security scan (cargo-deny) pending** — the fork's CI
  runs `cargo-deny check`; a full advisory/license gate for the pinned Buzz
  build is not yet part of this release's gate.
