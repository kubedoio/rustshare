## TODO-005: Evaluate SAML/LDAP demand after OIDC pilot

**Status:** DEFERRED

**What:**
- Evaluate whether SAML and/or LDAP support is needed after the first OIDC-based school/nonprofit pilots.

**Why:**
- The approved Phase 1 wedge is OIDC-first.
- Some schools may still rely on older identity systems, but this should be pulled by real pilot demand, not guessed up front.

**Pros:**
- Preserves likely next-step identity work without bloating the pilot scope.
- Creates a clear trigger for follow-up engineering work based on real customer evidence.

**Cons:**
- May never be needed if OIDC covers the target pilots.
- Expanding identity surface increases implementation, testing, and support burden.

**Context:**
- This /plan-eng-review explicitly chose DB-backed OIDC as the runtime source of truth.
- SCIM was deferred from the pilot gate.
- This TODO exists so future identity expansion does not turn into undocumented folklore.

**Depends on / blocked by:**
- At least one real OIDC-based pilot conversation or pilot attempt with a school/nonprofit admin.

## TODO-006: Define desktop-sync pilot readiness gate after web pilot

**Status:** DEFERRED

**What:**
- Define the explicit reliability, packaging, and support criteria required before the desktop sync client becomes part of a school/nonprofit pilot.

**Why:**
- The desktop client already has meaningful implementation, but this /plan-eng-review deliberately removed it from the Phase 1 pilot gate.
- Without a written readiness bar, desktop work can creep back into scope because it feels "almost done."

**Pros:**
- Protects the web-first pilot from scope creep.
- Gives future desktop work a concrete graduation checklist instead of vibes.

**Cons:**
- Adds another deferred planning item to track.
- The checklist may need refresh if desktop direction changes significantly.

**Context:**
- `desktop/src/main.rs` already supports login, sync add/remove, daemon, and status flows.
- `STATUS.md` still describes the desktop app as an early prototype, not a production client.
- This TODO exists to separate "code exists" from "safe to put in front of a school admin."

**Depends on / blocked by:**
- Completion of the OIDC-first web pilot and real feedback on whether desktop sync is mandatory for the next school/nonprofit pilot.
