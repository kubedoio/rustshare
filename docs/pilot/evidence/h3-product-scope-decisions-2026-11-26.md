# H3 product-scope decisions

As of protected main `d6bcbc9d4e4e5aebc6449b2b47267b267c3cf2e2`. #588 adds only a terms-independent invitation-race test fixture. These records bound the institutional pilot; they do not authorize FWS deployment or expand pilot scope.

| Issue | Pilot decision | Evidence and explicit deferrals |
| --- | --- | --- |
| [#325 Mail](https://github.com/kubedoio/rustshare/issues/325) | Keep live, server-authorized Mail as the default. Make durable archive/import an explicit opt-in with a chosen source, retention period, storage location, deletion behavior and Memory indexing policy. Do not silently archive whole mailboxes. | Live authorized search is implemented; selected IMAP import/archive machinery is a separate retention mode. Decide retention and privacy controls before enabling persistent archive by default. No durable Mail Memory index is qualified. |
| [#329 Calendar](https://github.com/kubedoio/rustshare/issues/329) | Keep the vendor-neutral iCalendar import/export boundary in pilot scope. | Calendar import/export and repeated-import idempotency, plus denial when linked content is unavailable, passed in the disposable journey. Defer authenticated subscriptions/feeds, unsupported recurrence/timezone cases, and provider-specific Google/Microsoft sync to explicit acceptance; #507 remains operator-credential dependent. |
| [#330 Organization administration](https://github.com/kubedoio/rustshare/issues/330) | Scope to organization administrators, ordinary users, groups, workspace membership and effective-access visibility. Reuse existing resource authorization; do not add school-specific roles or a second permission authority. | The d6 disposable Pilot Release passed, but its 100-user/two-admin browser journey is a separate PR #569 Pilot Release [45865650938](https://github.com/kubedoio/rustshare/actions/runs/45865650938), still in progress. Group removal/revocation regression merged in #574; full institutional acceptance remains open. |
| [#355 Rebranding](https://github.com/kubedoio/rustshare/issues/355) | Pilot uses deployment-wide build-time name, logo path and fixed palette configuration shared across tenants. | H1 configuration is implemented. Defer runtime admin editing, persisted per-tenant branding, expanded theme choices and secondary-surface legacy-copy cleanup until ownership and scope are approved. |
| [Chat authority](https://github.com/kubedoio/rustshare/pull/584) | Retain the current fork-backed Buzz deployment under bounded security/compatibility maintenance (D). Keep unmodified upstream Buzz as the previously approved strategic target (A), gated on independent identity, custody, authorization, security, interoperability and rollback acceptance. | RustChat is a substantial independent alternative, not a drop-in: tenant/Principal mapping, Files authorization, Memory provenance, data migration and rollback remain unimplemented/unqualified. No Chat migration or publishing is authorized. See [the H4 decision](../../architecture/chat-h4-decision.md). |

Owner decisions still required before scope expansion: Mail archive retention and opt-in defaults; Calendar feed/provider-sync priority; runtime or tenant-scoped branding; and any change to the accepted Chat target or current operating posture.
